# 规格：企业级落点范式（R-110 / R-111 / R-112）

Status: in-progress

> 需求编号：**R-110**（多租户上下文与权限点的唯一出处）· **R-111**（错误与重试策略的唯一出处）·
> **R-112**（E2E / 契约测试的落点）。
> 上游：架构审查（`.scratch/arch-review/review.md`）之后用户问"当前示例架构能否支撑企业级大型项目"，
> 结论是"骨架够、横切面缺"，用户在缺口清单里点了这三条。
> 本文档只写**场景 + 期望 + 验收**；判据与等级在实现时进 `docs/DESIGN.md`（架构性变更进 `docs/ARCHITECTURE.md`）。

## 场景

企业里这三件事的共同形状：**它们在单个域里都对，合起来就错**，而且错得安静。

1. **多租户串数据**（R-110）：租户 id 一个入口从 `searchParams` 取、另一个入口从 `user.tenant` 取、
   第三个入口忘了带 → 后端按默认租户返回，界面一切正常，直到客户发现自己看到了别家的数据。
2. **权限点散写**（R-110）：`can('crew:edit')` / `role === 'admin'` 散在组件里；权限模型改一次要全仓找，
   漏改的那一处就是越权入口（R-46 已经管住"判断写在哪儿"，但**权限点叫什么、在哪儿定义**没人管）。
3. **重试风暴**（R-111）：每个页面各自 `retry: 3`，一次后端抖动变成 N 个并发 × 3 次重试；
   谁也没接全局错误，白屏就是"白屏"，日志里分不清是哪个入口。
4. **错误文案三处三种说法**（R-111）：同一个 `RATE_LIMIT`，三个入口三种提示，客服拿日志对不上。
5. **测试分层塌掉**（R-112）：e2e 写在 `src/**/*.test.tsx` 里与单测混跑；e2e 直接 import 域内 `lib/`，
   改一次内部实现要改十个测试；契约测试没有落点于是没人写；`checkChain` 只跑单测，e2e 从未在 CI 执行。

## 期望（可判定的那一半）

| 需求  | 期望的"落点范式"                                                                                                                                      | 明确不判的                               |
| ----- | ----------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------- |
| R-110 | ① 租户上下文有**唯一来源**（声明的 provider/落点），别处取用即报 ② 权限点名有**唯一出处**（常量表，`can('字面量')` 即报）③ 请求经**带租户维度的封装** | 谁有哪个权限、策略怎么配（业务语义）     |
| R-111 | ① 失败处理的**策略**只许来自声明的落点（形态 + 数字，D20 的推广）② 错误码 → 文案的映射有唯一出处 ③ 全局错误呈现有落点                                 | `catch` 里该做什么（重试 / 降级 / 上报） |
| R-112 | ① 测试**分层有声明**（单测 / e2e / 契约各自的角色与落点）② e2e **只许经公开面/应用入口** ③ `checkChain` 能表达"CI 里真的跑了哪几层"                   | 测多少、覆盖率够不够                     |

## 复用与边界（这三条都不该发明新机制）

- **唯一出处族**（D22 缓存键 · D23 路由 · D24 事件名 · D25 端点 · D26 键形状）：R-110 的"权限点"、
  R-111 的"错误码映射"是同一形状 → 同一套 `requires` + 面 + 夹具写法。
- **落点族**（S36 取数 · S38 调用落点 · S41 客户端状态 · S44 环境读取）：R-110 的"租户上下文来源"、
  R-111 的"全局错误呈现"照抄这一套。
- **角色表与公开面**（S23 / S04 / S05 / S22 与 R-105 `@x`）：R-112 的"e2e 只经公开面"直接复用 ——
  e2e 目录是**另一个组**，规则侧只换声明。
- 不新造机制：凡是能用"角色 + 面 + 唯一出处"表达的，不许写临时代码；判不动的（语义）一律明列不做。
