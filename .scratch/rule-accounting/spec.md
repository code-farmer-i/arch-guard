# 规则账目：注册了却没跑，要说得出是哪几条、为什么

Status: done

## 场景（对应 REQUIREMENTS.md 的 R-142）

- **把一条规则从启用名单里移出去**（改预设的 `enable`、或自定义规则没被列进去）时：
  唯一的信号是报告头 `规则 70/112` 的分子 −1 —— **分母不变、不点名、不给理由，也不问"这是有意的吗"**。
  **现在：不会报。** 实测 `dsh-workbench`：`70/112` 且只解释了 24 条（`因能力未声明而停用`）——
  **另 18 条既不在 `enabled` 也不在 `skipped`，报告一个字都不提**。
- **本仓自己**：`39/107` + 停用 14 → **54 条无人提及**；`examples/full-fsd`：`91/107` + 停用 7 →
  **9 条无人提及**（那 9 条是 R-87 明确允许缺席的应用专属规则 —— 有意的缺席，但报告同样说不出这是有意的）。
  `examples/full` 与 `examples/minimal` 是 0（账目本来是能闭合的）。
- **用 `--only` / `--domain` / `--min-level` 收窄**时：被过滤掉的规则同样一声不响
  （`registry.ts` 55–68 行三个 `continue`）—— 用户明确要求的收窄算"知情"，但**报告不该假装它们不存在**。

## 背景与问题

机制：`registry.ts` 只产出三个桶 —— `enabled` / `skipped`（**只收 `capability-missing`**）/ `unknownEnabled`。
「注册了但没跑」的规则落在三个桶之外。`codes.ts` 的注释早就写着这个缺口与扩展点：

> 规则**没跑**的原因（`skipped[].code`）—— 同样是契约…目前只有一种（能力未声明）；加新的就在这里加，并同步冻结测试

与 R-87 的分工（那条已标完成，别重复做）：R-87 修**清单本身**（范式无关的规则要在每个范式下注册，
并给 9 条应用专属规则开"允许缺席"的口子）；本条修**缺席的可见性** —— 允许缺席，但要说得出来。

## 目标

- **账目闭合**成为可判定的不变量：
  `全部注册规则 = enabled + Σ skipped(按 code) + 被 disable 的（已有 `rules-disabled` 自述）`。
- 新增两个 skip code（**不新增 `RegistryResult` 字段** —— 复用 `skipped`，公共类型不变）：
  - `not-enabled`：在规则集里，但不在当前 `enable` 名单里；
  - `filtered`：在名单里，但被 `--only` / `--domain` / `--min-level` 收窄掉了。
- 报告出**第三类自述**（按 code 分组，点名 + 原因 + 可执行处方）；`--explain <路径>` 把 code 讲成人话；
  `--explain <id>` 增一行「当前配置下：跑 / 没跑（为什么）」；`--list-rules` 每条标注状态。

## 非目标

- **不做预设级的逐条理由**（"S03 是应用专属所以本范式不适用"）：那是预设的散文，引擎不认识它，
  硬编码进 engine 会违反"引擎零宿主词汇"。v1 一律归到 `not-enabled`，理由指「当前 `enable` 名单」+ 怎么改；
  要逐条理由，就单开一条需求让**预设**声明它（可选，且要按 R-87 的口径归组）。
- **不把 `disable` 收进 `skipped`**：显式停用已经有 `rules-disabled` 自述（R-125），同一件事不许两处报。
- **不改 `apiVersion` / JSON 顶层字段**：`skipped[]` 本来就在，`SKIP_CODES` 加一项属兼容性新增
  （按 DESIGN §6.9：新 code 要同步冻结测试 + CHANGELOG 标注）。

## 验收标准

- 单测：**账目闭合**在多个配置上成立（`examples/{minimal,full,full-fsd}` + 本仓配置 + `--only` 收窄 +
  带 `disable` 的配置）—— 任何"注册了却没进任何桶"的规则都会让测试红。
- 单测：报告第三类自述在「有未启用」时出现并点名；**全跑光时一行都不出现**（`examples/full` 回归）。
- 单测：`--explain <id>` 对「跑」与「没跑」两种规则各给一行状态；`--list-rules` 的状态标注与 registry 一致。
- 单测：`skipped[].code ∈ SKIP_CODES`，且 `missing` **当且仅当** `code === 'capability-missing'` 时非空。
- `pnpm check` EXIT=0（Node 24.13.0）；发版前按仓库规矩补跑 Node 22.18.0。

## 边界与取舍

| 取舍                           | 决定                                                                                                                                                         |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 「本范式不适用」要不要单独一类 | v1 不单独分：引擎分不出"预设有意不给"与"预设漏了"，硬分就是编造。归 `not-enabled`，理由里指名**是谁给的名单**（`config.paradigm` / 项目 `overrides.enable`） |
| `filtered` 要不要点名到 id     | **不点名**：用户自己敲的 `--only S45` 不需要回显 106 个 id。只给条数 + 哪个过滤器                                                                            |
| 收窄到 0 条规则怎么办          | 已经有 `paths-no-match` / `exitCode=2` 的既有语义，本条不动                                                                                                  |
| 长行的可读性                   | 按 code 分组、每类一行（与既有 `因能力未声明而停用 …：S13 / S37` 同形状），不逐条占行（R-126 的信息架构）                                                    |
