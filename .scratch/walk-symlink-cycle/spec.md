# `walk` 的目录环：链接指回祖先时遍历无限下降

Status: done

## 场景（对应 REQUIREMENTS.md 的 R-151）

- **宿主的仓库里有一个指回上层的目录链接**（`ln -s .. src/back`，或 `link -> .` 这类写法）时：
  `walk` 没有环检测，会一路下降（`src/back/src/back/src/…`）直到 `ENAMETOOLONG` 才被 catch 终止。
  **现在：不报错，但报告被幻影路径淹没** —— 同一棵只有 2 个真文件的树返回 **32 个文件**（**30 个幻影**）；
  盘点时在真宿主上实测 **66 个 error**。
- 更要紧的是幻影路径**落在 `src/**` 契约域内**：它们会被当真文件判角色与依赖 →
  假 finding 淹掉真 finding，而报错信息里没有一个字提到"链接"。用户做的只是加了一个链接。

## 背景与问题

`walk` 的注释记着一条**有意**的语义：跟随目录符号链接（`Dirent.isDirectory()` 对链接返回 false，
所以链接要补一次 `statSync` 跟随）。这条语义是对的 —— workspace / monorepo 会把源码目录链接进来，
**不跟随 = 少判 = 静默假绿**，比误报更糟。

缺的不是"要不要跟随"，而是**"跟随到哪里为止"**：没有环检测，也没有"这条路已经走过"的记账。

## 目标

- **保留跟随**目录符号链接（既有语义与差分测试都不许变）。
- **切断环**：目录环一定穿过符号链接（目录硬链接不允许），所以
  - 只对**符号链接**付一次 `realpathSync`；
  - 非链接子目录的真实路径 = 父的真实路径 + 名字（**零 syscall**）；
  - 维护"当前这条路径已走过的真实目录"栈，命中即不进。
- 不成环的"两条路到同一个目录"（`alias -> real`）**照旧两边都收** —— 那是既有行为，不是本次要改的。

## 非目标

- **不改成"不跟随链接"**（即不用 `fs.globSync` / `fdir` 替掉 `walk`）：那会让链接进来的源码目录
  被静默漏掉，正好是这门禁最怕的失败模式。
- **不做"根包含"限制**（链接指到项目根之外仍会被跟随）：workspace 场景需要它；
  它带来的路径是 `../…`，在报告里以"域外 N 个文件不判契约"显形（响，不静默）。
  要禁止越界是另一条产品决策，另开需求。
- 不动 `classifyEntry`（悬空链接 / 无权限链接照旧整体跳过）。

## 验收标准

1. `pnpm check` 全绿；`--self-test` 97/97。
2. `tests/walk.test.mjs` 既有差分测试（`walk` vs 改动前算法，含链接目录 / 链接文件 / 悬空链接）**逐项一致**。
3. 新增环用例：`src/back -> 根` 与 `src/deep/up -> src` 同时存在时，
   `walk` 只返回真文件（`src/a.ts` / `src/deep/b.ts`），**一个幻影都不出现**。
4. 新增等价用例：`alias -> real`（不成环）时两条路都收。

## 边界与取舍

- **判环靠"真实路径链"而不是"全局去重"**：全局去重会让 `alias -> real` 的其中一条路消失（行为变更），
  而链上比对只挡真正的环。
- **性能**：链接目录才 `realpathSync`（原本就已经为它付了一次 `statSync`）；普通目录不加 syscall。
  这是刻意的 —— `walk` 上一轮刚做过"省掉每条目一次 `statSync`"的优化（1131 文件 2.1s → 0.47s），
  不能在这个热路径上退回去。
- **被否的方案**：换成 `fs.globSync`（0 依赖、天然无环）—— 它**不跟随**目录符号链接，
  等于把 workspace 链接进来的源码判成"不存在"。
