# glob 匹配换成 picomatch：手搓 glob 的欠匹配 = 静默不判

Status: done

## 场景（对应 REQUIREMENTS.md 的 R-149）

- **项目用字符类写 `include`**（`include: ['src/**/[a-z]*.ts']`）时：手搓的 `globToRegExp` 把 `[a-z]`
  **转义成字面量**（`\[a-z\]`）→ 一个文件都匹配不上 → 那些文件全部落到"契约域外"。
  **现在：不报错、不提示** —— 报告从 3 个 error 变成 1 个（`[S05]` 与 `[S08]` 一起消失），
  只在附录里从"域外 1 个"变成"域外 2 个文件不判契约"。S24 只在**整个**扫描域为空时报，**部分欠匹配零诊断**。
- **同一个宿主换一种写法**（`src/shared/**` → 同义的带字符类写法）就会得到不同的结论 —— 判据的输入是 glob，
  而 glob 的解释权在门禁手里，写对了却**静默失效**。

## 背景与问题

`globToRegExp` 是 41 行手写状态机，只认 `**` / `*` / `?` / 花括号字面量枚举。它的注释自认"宁可少匹配"——
对**报告**来说少匹配是"保守"，但对**门禁**来说少匹配就是"这条纪律不跑"：`include` 决定谁被判契约，
`ignore` 决定谁不被扫，角色表决定每个文件是什么。三处一起静默缩小，报告照样 ✔。

## 目标

- `globToRegExp` 的实现交给 **picomatch**（成熟、0 自带依赖、6.25 亿/周），**导出 API 不变**
  （仍是 `(glob: string) => RegExp`）→ 全仓 23 个调用点零改动。
- 新增能力：`[...]` 字符类、extglob。**三个兼容口径显式定住**（写进代码注释 + 本规格）：
  ① `dot: true`；② 尾随 `/**` 再补一层 `/*`；③ `nonegate: true`。
- **加一层编译缓存**：picomatch 的编译比手搓慢约 4×（8 个 glob 一轮 14.8µs → 58µs），
  而仓里有几处是**按文件**编译的 —— 缓存后同一轮 **2.2µs**（比旧实现还快 ~7×），
  返回的仍是新 RegExp 实例，调用方互不影响。

## 非目标

- **不引入 `!` 取反语法**：旧实现把首字符 `!` 当字面量，凭空多一套语义属于行为变更，
  要支持就另开需求（配文档 + 夹具 + 迁移说明）。
- **不改调用方形态**：不做 `RegExp` → `matcher` 函数的迁移（那样 23 个调用点都要动，收益为零）。
- 不动 `walk`（符号链接环 / 越界是另一条需求，见盘点文档 B）。

## 验收标准

1. `pnpm check` 全绿；`node es/cli.js --self-test` 97/97。
2. `tests/engine-unit.test.mjs`：
   - `src/**/[a-z]*.ts` 命中 `src/shared/lib/deep/x.ts`、不命中 `Format.ts`，且 `.source` **不含** `\[a-z\]`；
   - extglob `src/**/!(*.test).ts` 可用；
   - `**/*.ts` 仍命中 `.agents/x.ts`（点文件，与旧实现一致）；
   - `!x` 仍按字面量（不取反）；
   - **尾随 `/**`**：`src/**` 不匹配 `src` 自己、匹配 `src/a.ts`；
     `{slice}/{segment}/**` 不把文件名吃进 `{segment}`（`src/features/x/index.tsx` 不匹配、`.../ui/Filter.tsx` 匹配）。
3. 热路径不退化：同一份 glob 只编译一次（`REGEXP_CACHE`），一轮 8 个 glob 的重复调用 < 5µs。
4. 夹具 `include-custom` 的 `include` 改成 `['src/**', 'scripts/**/[a-z]*.ts']`：`gen.ts` 命中（→ S01 必报）、
   `Gen.ts` 在字符类之外（→ 域外不判）。**这条夹具在旧实现下会少报 S01**，是端到端回归锁。

## 边界与取舍

- **尾随 `/**` 的补层不是"手搓 glob"的回潮**：它是给**文件匹配器**定的口径（标准 globstar 的 `a/**` 也匹配
  目录 `a` 本身）。不补就会出现"文件名被当成捕获段"这种更难查的错：`fsd()` 的
  `{slice}/{segment}/**` 与切片入口角色撞车 → S01 歧义（实测）。
- **唯一的行为变化是"以前静默不匹配的 glob 现在能匹配上了"**：原来写错 / 写宽的 glob 会开始生效，
  报告可能多出条目 —— 那是修复，不是回归；CHANGELOG 里写明这个方向。
- **被否的方案**：只给手搓版补一个 `[...]` 分支（能力补齐了，`{1..3}` / extglob / 转义规则仍要自己维护，
  而"glob 语义"正是最该借成熟实现的活）；换 `path.matchesGlob`（Node 内置、0 依赖）——
  实测**慢 143×**（每次调用重新编译）。
