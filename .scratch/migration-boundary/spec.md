# 迁移边界只出不进

Status: in-progress

## 场景（对应 REQUIREMENTS.md 的 R-48）

- **迁移永远做不完时**：`src/legacy/**` 是待迁走的旧代码，但新写的
  `modules/orders/lib/price.ts` 里 `import { oldPrice } from '@/legacy/pricing'` ——
  legacy 从"待清理"变成"事实上的核心"，越迁越多。**现在：不报**。
- **人数一多就失控时**：三个人各自"先复用一下老代码"，三个月后没人说得清 legacy 还有没有在长。
  **现在：不报**。
- **层号救不了**：给 legacy 一个低层号只能挡"向上依赖"，挡不住"新代码往下顺手引用它" ——
  那正是迁移边界要挡的方向。**现在：不报**。

## 目标

- 项目声明哪些路径**在迁移中**（glob 列表）之后：**外面引用它们就报**；
  它们自己引用外面（"只出"）与新代码无关的引用都不报。
- 报在**引用方**（新代码）那一行上 —— 要改的是它，不是被引用的旧文件。
- 迁移中的路径可以在契约之外（`src/legacy/**` 通常没有角色）：规则用解析后的真实路径判定，
  所以"被引用方不在角色表里"也能判。

## 非目标

- 不强制"迁移必须完成"（没有任何时间概念），也不统计迁移进度。
- 不判"旧文件该不该删"（那是 H12 退路残留管的**文件名**层面）。
- 不追溯历史（不提供存量豁免）：声明之后新出现的**任何**引用就报。

## 验收标准

- 夹具 `migration-boundary`（违规必报 × 合规不报）：
  - `modules/crews/lib/price.ts` 引用 `@/legacy/pricing` → **报**；
  - `legacy/pricing.ts` 自己引用 `@/shared/lib/format` → **不报**（只出不进）；
  - 其它域不碰 legacy → 不报。
- 单测：未声明 `migrating` → 不报；glob 命中判定按解析后的路径（别名 / 相对路径都能判）；
  迁移目录之间互引不报；`migrating` 里放空串或非字符串 → 解析配置时直接报错。
- 双 Node `pnpm check` EXIT=0；DESIGN §5.1 有 S40 行、规则数与夹具数口径同步。

## 边界与取舍

- **只判契约内的引用方**：`vite.config.ts`、脚本、e2e 引用 legacy 不算架构违规（它们不归目录契约管）——
  与 S36/S38 的"只迭代 records"一致。
- **只出=合法**：迁移目录引用新代码是**目的**（逐步替换），所以方向只有一个限制。
- **不动 @ 之外的东西**：不自动改 import、不生成迁移清单（门禁只判，不修）。
- **声明没匹配到文件**：不报（可能刚好迁完了）。真要收口就把声明删掉 ——
  这条留作"声明必须能被证伪"的已知缺口，记在需求 R-51 那一类里。
- **被否方案**：把"迁移中"表达成层号（给 legacy 最低层）—— 那会顺带允许它被任何人引用，
  正好是这条要挡的；表达成角色（给 legacy 一个角色）—— 又要求它落进目录契约，
  而迁移中的代码通常恰恰不符合契约。
