# 与 lint 生态的交叉审计

**目的**：确认本门禁**不与已有工具重复**，并留下可复查的依据。
**判定规则**（本项目自己定的线）：

> 纯语法 / 纯图属性，且**不需要项目专有数据**（角色表、适配器、能力表）的约束 → 委派给现成工具；
> 需要这类数据的 → 本工具实现。

> 本文逐条回答「这条规则生态里谁在做」；**整包替代品有没有、拼出来能到几成**见
> [`ALTERNATIVES.md`](./ALTERNATIVES.md)（成熟工具组合、FSD 场景、steiger 的边界、结构声明化方向）。

**复查方式**（可复现）：

```bash
npx oxlint --rules | grep -i <关键字>          # oxlint 实现清单
node -e "const {builtinRules}=require('eslint/use-at-your-own-risk');console.log(builtinRules.has('no-magic-numbers'))"
npx arch-guard --list-rules                     # 本工具当前规则清单
```

## 1. 已经委派出去的（不再是我们的能力）

见 [`DESIGN.md` §4.9 委派清单](./DESIGN.md)：单文件语法卫生（any / console / debugger / 空 catch / 未完成标记）、
假异步与随机、硬编码地址、假数据、文件与函数行数、`../` 越级、依赖环、孤儿文件、幽灵依赖与未使用依赖、
颜色字面量、`!important`、长度/层级/时长白名单、JSX 裸文案 —— 逐条去向在 §4.9 表里列出。

> **修订：文案键的对账没有被委派出去。** `eslint-plugin-i18next` 只有 `no-literal-string` 一条规则
> （`Object.keys(plugin.rules)` 实测），不做键存在性与未使用键；当初按「插件能顶 C01 · C02 · C06」删掉
> 后两条，是把插件能力估大了。C02 / C06 已恢复实现（见 §4 表）。

**实测记录**：同一份代码上，eslint 与旧版本工具的 7 条发现**同行同类**（`no-console`↔H03、
`no-explicit-any`↔H01、`no-non-null-assertion`↔H01、`no-debugger`↔H03、`no-empty`↔H05、
`ban-ts-comment`↔H01）；这正是它们被删掉的理由。

## 2. 现在保留的规则：逐条交叉判定

### 2.1 生态无法表达（真独有）

| 规则              | 判据性质                                         | 为什么现成工具做不到                                                            |
| ----------------- | ------------------------------------------------ | ------------------------------------------------------------------------------- |
| `S01` `S03`       | 角色表互斥完备 / 域根只许 routes                 | 「路径即角色」是项目自己的契约，lint 没有角色概念                               |
| `S02`             | 目录深度                                         | 与角色表绑定；lint 无布局模型                                                   |
| `S14`             | 有 views 必须有 routes.tsx                       | 需要「槽位配对」语义                                                            |
| `S15`             | routes 必被 app 聚合 / view 必被本域 routes 引用 | dependency-cruiser 有 `required` 能力，但要重写一层路径语义                     |
| `S17` `S18`       | 导出名跨文件查重 / shared 单域使用               | 无等价规则（`no-redeclare` 只在同一作用域内）                                   |
| `D04` `D05`       | 令牌引用闭合 / 死令牌                            | 需要**跨文件令牌图**；`stylelint-value-no-unknown-custom-properties` 只查文件内 |
| `D06`             | 明暗两套令牌名一致                               | 需要按主题块配对比较                                                            |
| `D07`             | 对比度基线（含半透明合成）                       | 需要令牌求值 + WCAG 计算                                                        |
| `D08`             | storage key ↔ `index.html` 内联脚本              | 跨文件（TS 常量 ↔ HTML）一致性                                                  |
| `D10` `D10b`      | 组件库选择器只许 vendor / vendor 反向封闭        | 依赖**适配器数据**（哪个库、哪些前缀）                                          |
| `D11`             | 无框架残留                                       | 依赖适配器指纹表（换库即换数据）                                                |
| `D16`             | 自研样式只在 `*.module.css`                      | 路径与所有权规则，stylelint 只能按文件匹配、不能判「这个文件不该存在」          |
| `D17`             | CSS Module 双向契约                              | 需要 CSS ↔ TSX 双向引用分析                                                     |
| `C03` `C04` `C05` | 多语言同构 / 一文件一命名空间 / 分片必须被聚合   | i18next 插件只做键存在与未使用，不看目录同构与聚合图                            |
| `P01` `P02`       | **批准清单**策略（未登记即拒）                   | knip 按 manifest 查，查不了「批准了什么」                                       |
| `P04`             | 适配表声明的包 vs 实际依赖                       | 需要适配器数据                                                                  |
| `P05`             | 图标来源唯一                                     | 依赖适配器登记的图标包                                                          |
| `P06` `P07`       | 能力必须用登记方案 / 疑似自造轮子                | 依赖能力指纹表与项目选型                                                        |
| `M06`             | 覆盖率产物**必须存在且新鲜**（fail-closed）      | 没有工具做「产物缺失/过期就拒」这件事 —— 它是门禁与测试链路之间的胶水           |
| `M07`             | 依赖数量预算                                     | 没有主流工具做「预算」这件事（knip 不做计数上限）                               |

### 2.2 生态能表达，但需要把项目数据重抄一遍（按设计保留）

| 规则        | 近似工具                                                                | 保留理由                                                                                            |
| ----------- | ----------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| `S04`–`S09` | `eslint-plugin-boundaries`、`dependency-cruiser`                        | 它们需要另写一套 element-types / forbidden 规则，等于把角色表抄一遍；我们复用同一份数据，零额外配置 |
| `S11`       | 无（实测 oxlint 无 barrel 规则）                                        | ——                                                                                                  |
| `S12` `S13` | `eslint-plugin-filenames`、`naming-convention`、`no-restricted-exports` | 这些按「目录角色」判（views→`*Page`、hooks→`use*`、api→小写 camelCase），需要按目录逐条 overrides   |
| `S16`       | `max-lines`（已委派）；`exportsPerFile`/`componentsPerFile` 无现成      | 保留的是**没有等价实现的那一半**                                                                    |
| `H06`       | 社区 antd 规则部分覆盖                                                  | 我们是**适配器驱动**（换组件库只换数据），社区规则绑死单库                                          |

### 2.3 与测试运行器自带阈值部分重叠（作为「不依赖运行器」的替代保留）

| 规则        | 近似能力                                | 说明                                                                                                           |
| ----------- | --------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| `M02` `M03` | vitest/c8 的 glob 阈值、`perFile: true` | 宿主用 vitest 时开它自己的阈值即可；我们的实现面向「运行器没有阈值能力」或「不想把阈值写在运行器配置里」的场景 |
| `M04`       | jest-coverage-ratchet 之类的社区工具    | 我们的快照由 `--update-baseline` 一并维护                                                                      |
| `M05`       | `diff-cover`                            | 我们是文件级、零依赖；diff-cover 是行级、更强                                                                  |

> **总阈值（M01）故意不实现**：vitest / jest / c8 都自带 `thresholds`，用 `perDirMin: { 'src/**': 95 }` 就能表达同样的意思。
> **产物体积预算（M08）故意不实现**：`size-limit` / `bundlewatch` 已经有成熟实现。

## 3. 引擎与 CLI 能力

| 能力                                                            | 交叉情况                                                                                 |
| --------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| 夹具回归（每条规则「违规必报 × 合规不报」）                     | 独有（lint 生态没有「规则的规则」）                                                      |
| 棘轮：基线按**行文本锚点**豁免                                  | 生态有「按 rule+file 计数」的 ratchet 插件，但按行文本锁定是我们防「改一行就绕过」的做法 |

| `--verify-deps`（适配表 ↔ 依赖对账）                            | 与 knip 部分重叠，但我们的输入是**适配表**，knip 是 manifest                             |
| `--format=github`                                               | 独有（避免引入 reviewdog 依赖）                                                          |
| `--stats`（规则耗时与命中）                                     | 独有（用于规则退役决策）                                                                 |
| `specVersion`（配置/基线/适配器）                               | 独有                                                                                     |
| `definePack()`                                                  | 独有                                                                                     |

## 4. 本次审计新发现的重叠（**已按判定规则处理**）

| 候选                         | 等价实现                                                                                                                                                                                                                                                                 | 建议                                                 |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------- |
| `H02` 禁 `eslint-disable`    | `eslint-plugin-eslint-comments` 的 `no-restricted-disable` + `--report-unused-disable-directives`（零项目数据）                                                                                                                                                          | **删除**（按判定规则属完全重复）                     |
| `D15` 内联样式纪律           | `no-restricted-syntax` 选择器抓 `style={{ … }}` 里的裸数字与颜色字面量（零项目数据）。**注意 `no-magic-numbers` 不行**：ESLint 默认 `detectObjects: false`，对象字面量里的值它不管；oxlint 的同名规则没有该选项（且处于 nursery），实测对 `style={{ margin: 8 }}` 0 命中 | **删除**（宿主改用 `no-restricted-syntax` 落地）     |
| `D02` 色板只放色板令牌       | stylelint `custom-property-pattern` + `overrides`（一个 pattern）                                                                                                                                                                                                        | **删除**                                             |
| `C02` / `C06` 键存在性与死键 | **没有等价实现**：`eslint-plugin-i18next` 只有 `no-literal-string`（不做键对账），别的生态工具也不碰"这个键有没有人用"                                                                                                                                                   | **恢复实现**（当初按插件能力删除属误判）             |
| `D18` 组件只消费语义令牌     | stylelint `declaration-property-value-disallowed-list`（一个 token 前缀）                                                                                                                                                                                                | **删除**                                             |
| `D04` 引用闭合               | `stylelint-value-no-unknown-custom-properties` 只查文件内                                                                                                                                                                                                                | 保留（我们是跨文件令牌图）                           |
| `M02`–`M05`                  | vitest glob/perFile 阈值、`diff-cover`、社区 ratchet 工具                                                                                                                                                                                                                | 保留但**默认不启用**，仅当宿主运行器没有对应能力时开 |

### 4.1 测试相关门禁的专项结论（实测）

| 测试相关能力                        | 工具                                             | 覆盖           | 处置                                                |
| ----------------------------------- | ------------------------------------------------ | -------------- | --------------------------------------------------- |
| 覆盖率总阈值                        | vitest / jest / c8 `thresholds`                  | 完全           | 不做（M01 故意留空）                                |
| 目录级 / 每文件阈值                 | vitest glob 阈值 + `perFile`                     | 完全           | M02/M03 降级为「运行器无关替代」，默认不启用        |
| 变更覆盖率                          | `diff-cover`（行级，更强）                       | 完全           | M05 同上                                            |
| 覆盖率棘轮                          | `jest-coverage-ratchet`（老包）/ Codecov 基线    | 部分           | M04 保留（零依赖，与 `--update-baseline` 同处维护） |
| **产物缺失/过期 fail-closed**       | **无**                                           | —              | ✅ M06                                              |
| `.only` / `.skip` / 空测试 / 无断言 | oxlint 的 jest 规则、`eslint-plugin-vitest/jest` | 完全           | 不做                                                |
| 浮动 Promise                        | typescript-eslint `no-floating-promises` 等      | 完全           | 不做                                                |
| 死快照                              | jest `--ci` 报 obsolete                          | 部分           | 不做                                                |
| 易碎 / 顺序 / 超时                  | `jest --randomize`、retry、shard                 | 完全（运行期） | 不做                                                |
| 变异测试                            | `stryker`                                        | 完全           | 不做                                                |
| **测试↔源配对**                     | **无**                                           | —              | ✅ M08                                              |
| **门禁链路自检**                    | **无**                                           | —              | ✅ M09                                              |

处理结果：`H02` / `D15` / `D02` / `D18` 四条**已删除**（规则 48 → 44），
`D04` 与 `M02`–`M05` 按上表理由保留。结论：**当前 44 条里不再有「零项目数据的完全重复」**；
其余保留项（§2.1 / §2.2 / §2.3）都能说出「为什么现成工具做不到或需要重抄项目数据」。
