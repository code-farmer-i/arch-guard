# 红线只落在可判定等级（L1–L3）

门禁每条 error 级规则都必须只用「路径 / 单文件 AST / 依赖图」就能判定；语义判断（命名好不好、该不该拆、是否业务中立）不写进红线，只列进「门禁不做的事」。这条由 `createRule()` 代码强制：error + L4/L5 直接抛错。

理由：门禁要长期活在 CI 与 agent 循环里，误报会把门禁本身变成噪音，然后被关掉。宁少勿滥。

## Considered Options

- **用 `no-magic-numbers` 一类规则查语义** —— 它是 L5 伪装成 L2：判不了「这个数字值不值得命名」，实测靠 ignore 列表续命。改法是把魔法数字定义成「有家的字面量」（`mustReference` 的实例），只在登记过的语义域里查。
- **槽位按语义定义**（「`ui/` 放无业务语义的组件」）—— 判不了。改成按**依赖档位**定义（禁 hooks / stores / api），判定等级降为 L3。
