# ADR-0008 运行时面（runtime）与面值：公开面的第二、第三档

- **状态**：已采纳（2026-09-27）—— **延伸** ADR-0007（域有两个公开面），不取代它
- **关联**：R-139 · R-140 · 实测来源 [`dsh-workbench`](../../.scratch/faces/spec.md)（双运行时项目，2026-09-27）

## 背景

ADR-0007 给域开了第二个门（`index.ts` 业务公开面），并约定：

> `index.ts` **只导出实体 / 工具 / 类型**，不导出实现细节

—— **约定没有判据**。R-98 / R-105 之后，「公开面」这条纪律定义到「门在哪、组外只能从门进」，
还剩两件事没人管：

1. **谁该走哪扇门**。S23 的 `entry` 是**无差别通行证**。双运行时项目（宿主 Node 半侧 + 浏览器半侧）
   里一个域有两个**运行时面**：宿主面 `index.ts`、浏览器面 `client.ts`。「宿主侧只能走宿主面」是
   **配对**约束，而两条现有路都不通：
   - **S21 层号是全序**，只能表达「向下依赖」：要同时满足「宿主可进宿主面」「宿主不可进浏览器面」
     「浏览器可进浏览器面」「浏览器不可进宿主面」，需要一个既 `index ≤ host < client ≤ browser`
     又 `index > browser` 的序 —— 矛盾。
   - **S22 只禁不配**：同维度、同层、不同组 → 报。把两个面当两个组，会让**该放行的**
     「宿主侧 import 宿主面」变成跨组被报 —— 方向正好反了。
2. **门后能拿什么**。从公开面里 import 实现细节（`createIssuesService`），S23 一声不响。

**实测**（`dsh-workbench`）：层序表把 `modules/*` 与 `app/layouts` 放在**同一层**，
于是「外壳 import 套件内部」在层号上完全合法；项目只能自己造 **两套** 机制 ——
`scripts/check-runtimes.mjs`（跑真实 Vite 构建收集模块图）+ 五条自定义规则（S60–S64）。
而那五条里负责「面解析」的一段，**一轮重构内漂移两次**：

- `@/x` 只 `slice(2)` → 得 `modules/x`，后面却按 `src/modules/…` 匹配 → **规则在跑但永不报**；
- 补上 `src/` 前缀后，裸面路径 `@/modules/issues` 解析出的深度是空串、却没算作面
  → **把「从面进」误报成「走了内部」**（把正确写法判红）。

引擎里本来就有 `resolveSpecifier` 干这件事。**用手搓替代引擎的代价，已经在真实项目上兑现了。**

## 决策

1. **字段叫 `runtime`，不叫 `face`**。本仓已有 `facet`（**方案面**：router / styles / data-layer…，
   `defineFacet` / `facetNames`）与「公开面」两个词；再引入 `face` 就会出现两个「面」，
   报告、配置、文档里都会歧义。语义本来就是运行时。

2. **面按声明圈定，不按角色的 `slot` 猜**。`library()` 范式的域目录**没有 group / slot**
   （`lib:modules/issues` 只是一个目录角色），所以面挂不到角色字段上。改成 `structure` 里的两条声明：

   ```ts
   structure: {
     runtimes: [{ name: 'host', entries: ['src/app/host.ts'] },
                { name: 'client', entries: ['src/app/client.tsx'] }],
     faces: [{ pattern: 'src/modules/*/index.ts',  runtime: 'host',   value: '*Host' },
             { pattern: 'src/modules/*/client.ts', runtime: 'client', value: '*Client' }],
   }
   ```

3. **消费者的运行时用「可达性」推导，不逐文件标注**。文件 A 的运行时集合 =
   `{ r | A 从 r 的某个入口可达 }`。于是 **同构模块天然同时属于两个运行时**（可用任意面），
   而「只有浏览器能到」的文件不能进宿主面。这正是 workbench 自己的脚本最终收敛到的判据 ——
   它第一版按目录划，立刻把 `modules/sessions/model/session-node.ts` 这个纯函数域模型误判了。

4. **只判兼容性，不判完备性**。实测的面是**参差不齐**的：`issues` 两面都有、`panels` 只有宿主面、
   `sessions` 只有业务公开面。所以**不做**「每个声明的面都必须有入口」—— 那在这类项目上会直接误报。

5. **面值在提供侧判**（面文件只许导出面值），不在消费侧逐条对账：提供侧成立时消费侧自动成立，
   而且判据只有一趟（比 S45 那样逐 import 对账更省、误伤面更小）。名字模式是**数据**
   （glob，如 `*Host`），类型导出豁免 —— 于是**零事实模型改动**（`ImportFact.names` 已在事实里，
   不必动 `FACTS_CACHE_SPEC`）。

6. **判据进 S23，不新开规则号**。「公开面」这条题目已经有 ①组必须有入口 ②组外不许绕过 ③无组单元
   也要有入口；运行时面与面值是同一题目的第 ④ ⑤ 档。同题不加号，省掉一整套计数同步。

## 后果

- **好处**：双运行时项目不必再自造「面」（workbench 的两条自定义规则 + 构建图闸门可以退回本体）；
  `runtime` 是**不透明字符串**（host / client / worker / edge 都行），引擎零宿主词汇。
  可达性判据还能**静态**复现他们那条构建图闸门（构建图只在真的拖进 Node 代码时才炸，
  静态图能提前一步）。
- **代价**：S23 变成四档（入口 / 隔离 / 兼容 / 面值），「一条规则一件事」被推了一格 ——
  标题仍是「公开面」，可接受；**v1 边界**：只做「运行时相等即兼容」，不做任意兼容矩阵。
- **`faces[].pattern` 是显式 glob**（不按「是不是套件」推）：所以 workbench 的 `sessions`
  （业务公开面、被浏览器消费、两面都不算）**不会**被圈进去。用 `src/modules/*/index.ts` 这类 glob 时，
  模式必须自己圈得准 —— 圈不进的域就别列。
- **空声明即不判**：`runtimes` / `faces` 没声明时两档都不跑，与 `isolate` / `publicApi` 同一口径，
  既有宿主零影响；声明了却 0 命中由报告自述（R-86 / R-114 同族）。
- **与 S15 的分工**：可达性为空集的文件（孤儿）**不判**运行时面 —— S15 已经报孤儿，
  两条规则不许对同一件事各报一句。
