# 同一引擎服务两类工程形态：应用与库

`canonical()` 用三根拓扑（装配 / 业务域 / 共享）+ 域路由分片 + 别名规则；`library()` 用入口 / 引擎 / 预置 / 数据的分层，并关掉别名与路由那两条应用专属规则。差异只体现在预置贡献的**角色表 + 规则集**上，引擎一行不改。

发现过程：把门禁跑在自己仓库上（狗粮），第一次报 20 个 error —— 全是拿应用规则量库。库没有业务域、没有路由分片，内部相对导入是 Node 生态的常规写法。

## Considered Options

- **一套规则全开，让库项目写豁免** —— 豁免会淹没真正的违规；而且「所有规则默认常开」本身就是错的：规则集必须跟着工程类型走。
